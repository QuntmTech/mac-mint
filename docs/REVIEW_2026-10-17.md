# MacMint independent review — 2026-10-17

Reviewer: Claude Code (Opus 5.5), at the user's request and per `HANDOFF.md`.
Source reviewed: `main` @ `c0ade0e` (last implementation commit; `783d710` only changes docs).
Method: every file in `Sources/`, `backend/pocketbase`, `.github/workflows` and `scripts/` was read by subsystem. The highest-severity findings were re-read and verified line by line. New regression tests were run against the original code and failed. Production was inspected with read-only GETs only.
Not done: nothing ran on a physical Mac, and nothing in production was changed.

## Verdict

The trust architecture is real: a shared planner and executor, write-ahead journals, idempotent History, the restore no-overwrite rule, session generations, and transactional payments and AI reservations. Most documented safety claims hold.

The review still found:
- **1 High data-safety defect.** Excluding an app made its live data look orphaned.
- **2 High front-end defects.** View bodies run the planner and filesystem syscalls on every redraw, and the menu bar opens a new main window on every click.
- **1 High reliability defect.** Ordinary server errors lock out paid users.
- **4 High backend/commercial gaps.** Forgeable offline access, no rate limits, refunds that don't revoke access, and unverified update downloads.
- **Production drift.** Production runs an older backend generation than `main`.

None of the High items were caught by the existing 220-test suite or the 113 renders.

Severity scale: **High** means user data, money or access is at risk, or there is a clearly user-visible failure. **Medium** is a real defect with limited blast radius. **Low** is hygiene or polish.
Status column:
- `#28` = core safety
- `#30` = app reliability
- `#31` = backend, AI accounting and release hardening
- `#32` = signed entitlements and account resilience
- `open` = recommended, not yet implemented
- `ops` = operator action required

All four fix PRs are green on macOS 15/26 and the backend/web checks.

## Follow-ups found while fixing

- **Signing cost (#32).** Ed25519 signing in Goja takes 1.2–5 s per new assertion. Reuse (12 h) keeps typical `/me` calls at ~10 ms. Rate-limit `/devices/*` (#31) before deploying. Consider issuing assertions from a separate background endpoint or a native signer if activation volume grows.
- **No branch protection on `main` (#31).** The release workflow's "tag must be on main" check can be bypassed until `main` is protected and a `v*` tag ruleset exists.
- **Won disputes (#31)** don't restore access automatically; an operator re-grants it.
- **Proxy timeout (#31).** Review and organize now wait up to 90 s on the server (the app waits 100 s). The CloudPod proxy read timeout must be at least 95 s.
- **Disk reads in the review list (#30).** `PlanItemRow` still stats each item per render. `loadLeftovers` clears the previous app's leftovers before `beginScan` can refuse.
